# Marketplace one-shot Unix HTTP/1.1-to-ASGI adapter — source-only

**Status: reviewed source candidate, not wired, not deployed.**
**Canonical intended origin:** https://marketplace.open-trust-layer.org/ on the existing open-trust-layer.org VPS.
**Base:** protected main at `84aed548c828628613eea1091b51d8e64b50497b`.

## Problem

PR #590 provides a real Linux kernel `SO_PEERCRED` verifier, but traditional ASGI server frameworks do not automatically preserve the accepted connection's Python Unix-socket object in the HTTP scope. Without a reviewed connection-owning server, successful unit-level peer attestation cannot be safely attributed to individual HTTP requests. Forged forwarding headers or a TCP loopback connection must never substitute for socket peer identity.

## Scope

The new `serve_one_attested_unix_http11` is a **single accepted Unix connection** adapter. It does not bind, create or accept a socket, start a daemon, import Caddy, open a public port, install a service, access a database, provision credentials or alter persistent state. Its caller must supply an **actual accepted AF_UNIX stream socket** and the exact `MarketplaceAttestedCaddyEdgeAsgiAdapter` with the concrete `MarketplaceLinuxUnixCaddyPeerVerifier`. Any other provider type fails without serving a request.

The adapter checks kernel peer credentials before reading any HTTP bytes. It then reads a *single*, bounded HTTP/1.1 request with a six-second total deadline. It rejects ambiguous routing and framing, `Transfer-Encoding` and chunked requests, `Expect`, upgrades, invalid/duplicate content length, oversize headers/bodies and HTTP pipelining in already buffered data. It builds the ASGI scope itself (including the **real accepted socket reference**), supplies one `http.request` body event, and delegates to the existing attested edge and canonical Host/Origin guard. The edge strips the private socket reference before any Marketplace product or auth handler.

The HTTP response is buffered under strict size/event/header bounds; hop-by-hop and cookie-setting headers are forbidden, content length is generated by the adapter, and the connection is explicitly closed after one response. Malformed requests produce fixed, non-reflective 400/408/413/431 responses; trusted-edge failures are 403; app/provider errors result in fixed 503 responses without exposing exception text, secret tokens or private socket references.

This is intentionally **not a full general-purpose HTTP server**. Only strict HTTP/1.1, Content-Length-framed requests and one response per connection are supported. No HTTP/2, chunked framing, WebSockets, TLS termination, pipelining, persistent connections, compression, automatic server process supervision, rate limiting, buffering to disk, independent ingress authorization or trusted proxy construction is provided. Caddy's **actual request forwarding/framing compatibility remains unverified**, and unknown/unsupported real traffic must fail closed.

## Still missing before any hosted alpha

A separate reviewed service must establish a least-privileged Caddy identity, a distinct Marketplace identity, a real **OS-permissioned** AF_UNIX socket/listener with exact directory ownership and mode, Caddy's Unix upstream config, lifecycle and restart semantics, per-connection concurrency caps and global backpressure, integrated structured/redacted logging and metrics, rate limits, timeout and cancellation handling, and a real backup/restore path. This source-only helper does **not** implement or authorize socket listener creation, loopback-to-public proxying, Caddy mutation, TLS issuance, PostgreSQL provisioning or the seller/buyer production runtime. External Marketplace TLS/SNI has failed independently in previous read-only tests.

Marketplace invitation-only alpha remains blocked on genuine authenticated two-user signing/provisioning, Agreement publication, seller-attributed delivery evidence and equivalent Evidence V1 PASS—not just the manually closed owner issue #525. Payment/settlement/public signup remain disabled. See [hosting issue #528](https://github.com/open-trust-layer/marketplace/issues/528).

## Test and rollback

```sh
PYTHONPATH=src:. python3 -m unittest tests.test_unix_http11_asgi tests.test_linux_unix_caddy_peer tests.test_attested_caddy_edge tests.test_canonical_origin_guard -v
```

Linux tests use only ephemeral local temporary Unix sockets in the test runner: one accepted connection, real kernel peer identity, positive GET/POST ASGI requests, malformed Content-Length, request smuggling attempts, unsigned cross-origin POSTs, forged forwarding headers and fixed fail-closed results. **No live VPS or external network is touched.** OS-specific positive tests are skipped on Windows, with independent Linux test receipt required.

Future deployment must be a **distinct scoped action** with an explicit owner-approved implementation, real Caddy-to-ASGI HTTPS staging integration tests, service/DB isolation, and rollback. Reverting this source PR removes the helper; there is no production state to revert.
